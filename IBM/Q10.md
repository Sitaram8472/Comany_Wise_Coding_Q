# Q11. Implement a Custom Thread Pool in Java

## Problem Description
How do you implement a custom thread pool in Java?  
A custom thread pool can be implemented using the `ExecutorService` interface and the `ThreadPoolExecutor` class.

---

## Approach
1. Create a `ThreadPoolExecutor` instance with customized parameters.
2. Set the **core pool size** to `5`.
3. Set the **maximum pool size** to `10`.
4. Set the **thread keep-alive time** to `60` seconds.
5. Use a `LinkedBlockingQueue` to store pending tasks.
6. Submit tasks to the pool using the `submit()` method.
7. Call `shutdown()` to gracefully terminate the executor service after task completion.

---

## Code (Java)

```java
import java.util.concurrent.ExecutorService;
import java.util.concurrent.LinkedBlockingQueue;
import java.util.concurrent.ThreadPoolExecutor;
import java.util.concurrent.TimeUnit;

class RunnableTask implements Runnable {
    @Override
    public void run() {
        System.out.println("Task is running...");
    }
}

class Solution {
    public static void main(String[] args) {

        ExecutorService executorService = new ThreadPoolExecutor(
            5,
            10,
            60,
            TimeUnit.SECONDS,
            new LinkedBlockingQueue<>()
        );

        executorService.submit(new RunnableTask());

        executorService.shutdown();
    }
}
```

---

## Explanation
- **Core Pool Size = 5:** The minimum number of threads to keep alive, even if they are idle.
- **Maximum Pool Size = 10:** The maximum number of threads allowed in the pool.
- **Keep-Alive Time = 60 Seconds:** Excess idle threads will wait for new tasks before terminating after 60 seconds.
- **Task Queue = `LinkedBlockingQueue`:** Holds tasks before they are executed.
- The thread pool manages thread lifecycle efficiently, re-using existing threads rather than creating new ones for every task.

---

## Complexity Analysis
- **Time Complexity:** Depends on the number and execution time of the submitted tasks.
- **Space Complexity:** $O(n)$ where $n$ is the number of queued tasks awaiting execution.
