# Q21. Implement the Saga Design Pattern

## Problem Description
Demonstrate a simplified implementation of the **Saga Design Pattern** in Java. The Saga pattern is used to manage distributed transactions across microservices by breaking a single global transaction into a series of local transactions. Each local transaction updates the database and publishes an event or message to trigger the next step. If a local transaction fails, the Saga executes a series of **compensating transactions** to roll back the changes made by preceding operations.

---

## Approach
1. **Local Steps:** Execute local transactions sequentially (e.g., creating an order, updating inventory).
2. **Error Handling:** Wrap local operations in `try-catch` blocks to intercept failures at any stage.
3. **Compensating Actions:** If a downstream service call fails, execute explicit undo logic (`compensateOrderCreation`) to restore system consistency without global 2PC (Two-Phase Commit) locks.

---

## Code (Java)

```java
class Order {
    // Order payload/metadata
}

class InventoryService {

    public static void updateInventory(Order order) throws Exception {
        // Simulate inventory logic or failure
        System.out.println("Inventory updated");
    }
}

class OrderService {

    public void placeOrder(Order order) {
        try {
            createOrder(order);
            InventoryService.updateInventory(order);
            System.out.println("Transaction completed successfully.");
        } catch (Exception e) {
            System.out.println("Step failed! Executing compensating transactions...");
            compensateOrderCreation(order);
        }
    }

    private void createOrder(Order order) {
        System.out.println("Order created");
    }

    private void compensateOrderCreation(Order order) {
        System.out.println("Order creation compensated (rolled back)");
    }
}
